## How It Works

1. **Detection**: `/setup-stack` scans your project for fingerprint files (package.json, requirements.txt, etc.)
2. **Matching**: Conditionals in `.claude/conditionals/tech-stacks/` define which templates to load
3. **Extraction**: Content is extracted from best practice files (frontmatter is stripped)
4. **Injection**: Clean content is injected between the canary markers below
5. **Tracking**: State is saved in `.claude/memory/loaded_templates.md`

## Philosophy

**Modular & Hot-Swappable**:
- Each tool/library gets its own template file
- Templates have frontmatter for detection, but it's stripped before injection
- Only relevant practices are loaded into this file
- Keeps context lean and focused

**Extraction/Injection Model**:
- Templates live in `.claude/best_practices/` (version controlled)
- This file is regenerated on-demand (can be gitignored if desired)
- Frontmatter stays in templates (for tooling), content goes here (for context)

**Progressive Disclosure**:
- Universal rules: `.claude/memory/.claude-memory` (always loaded)
- Session essentials: `claude-quick-ref.md` (session start)
- Tech-specific: This file (on-demand via `/setup-stack`)
- Temporary focus: `/context:testing` (session-only)
